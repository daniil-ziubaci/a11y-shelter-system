# Опыт: каталог животных на Astro

Страница каталога (`/[locale]/shelter/[slug]/catalog`), перенесённая с Next.js на Astro
для сравнения нагрузки на Cloudflare Workers. На живой сайт не выкладывается.

Использует общий код проекта из `lib/`, `types/` и `messages/` (через `@/`), разметку и классы
повторяет один в один.

## Результаты (13.11.2026, локально, 500 животных)

| | Next.js | Astro |
|---|---|---|
| Процессор на страницу, прогретый сайт | 42–55 мс | 13–16 мс |
| То же без накладных расходов локального workerd (~4 мс) | ~40–50 мс | ~9–12 мс |
| Процессор на первое открытие после запуска (3 замера) | 480–540 мс | 40–60 мс |
| Размер HTML страницы | 194 КБ | 76 КБ |
| Код сервера | 5,6 МБ | 1,4 МБ |
| Отличающихся пикселей (7 снимков: компьютер, телефон, меню, фильтры, языки) | — | 0 |
| Дерево доступности (10 проверок) | — | совпадает* |

\* Кроме пустой области `role="alert"`, которую Next добавляет для объявления переходов внутри
приложения. В Astro каждая страница загружается целиком, и заголовок объявляет сам браузер.

## Как повторить

1. Запустить локальный Supabase и заполнить его (500 животных).
2. В корне проекта: `npm run cf:build`, затем `npx wrangler dev --port 8787 --ip 127.0.0.1`.
3. Здесь: `.dev.vars` как в корне плюс `SITE_URL`, затем `npm install`, `npx astro build`,
   `npx wrangler dev -c dist/server/wrangler.json --port 8788 --ip 127.0.0.1 --inspector-port 9230`.
4. Из корня проекта: `node experiments/astro-catalog/measure/cpu.mjs 8787 300` и `… 8788 300`;
   `S=<папка для снимков> node experiments/astro-catalog/measure/compare-screenshots.cjs`;
   `S=<папка> node experiments/astro-catalog/measure/compare-aria.cjs`.

Процессорное время считается по `/proc/<pid>/stat` процессов workerd до и после серии запросов.
