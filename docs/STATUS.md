- **Владелец смотрит новый сайт у себя на компьютере** (Ubuntu): папка `~/shelter-astro`, отдельная локальная база Supabase в Docker (имя проекта `shelter-astro-local`, порты 55320–55329, адрес базы `http://127.0.0.1:55321`), тестовые данные из `scripts/seed-local.ts`, сайт `npm run preview` на `http://localhost:8787`. Публичные страницы владелец посмотрел, всё открылось; последний шаг — вход в панель тестовым волонтёром `volunteer@example.org` с настройкой двухфакторного входа. Подтверждения входа ещё не было.
- **Аудит ветки `astro` сделан 14.11.2026**: исправления, решения для владельца и то, что не удалось проверить, — `docs/AUDIT-REPORT.md`. Рассказ о проекте простыми словами — `docs/PROJECT-GUIDE.md`.
- **Пробный перенос из настоящей копии боевой базы не сделан**: нужен пароль копий, он есть только у владельца. Делается на его компьютере (шаг 2 ниже).

## Принятые решения

- Один приют, без `shelter_id` и адреса приюта в пути; старые адреса `/{язык}/shelter/live-life/…` отвечают 301 на новые.
- Новый пустой проект Supabase `live-life`; старый не переделывается, данные переносятся `ops/migrate/migrate.sh` (без `--apply` — только план).
- Дизайн как в Next: сравнено 86 пар скриншотов, совпадают; оставшиеся отличия объяснены в отчёте.
- Фото готовит браузер волонтёра; при замене фото старые файлы удаляет сервер, но только если на них больше никто не ссылается; если файла нет, карточка берёт основное фото, иначе — пустая плашка.
- Волонтёр, забывший пароль: `scripts/reset-password.ts`; потерявший телефон: `scripts/reset-2fa.ts` (`docs/RUNBOOK.md`).
- Копии: 7 самых новых копий базы не удаляются никогда.
- Кэш: публичные страницы — 60 с у Cloudflare; `/`, панель, вход, `/auth`, `/api` — `no-store`.
- На Cloudflare собирается и выкладывается только ветка `main`, сборки других веток выключены (проверено через API 13.11.2026).
- Ничего не отправлять без явного разрешения владельца на каждую отправку; в `main` не вливать (правила в `CLAUDE.md`).

## Порядок шагов до перехода на новый сайт

1. Владелец досматривает новый сайт локально (панель волонтёра) и решает, переходить ли.
2. Пробный перенос из настоящей ночной копии на компьютере владельца, без `--apply`: `ops/migrate/README.md`. Перед этим остановить локальную базу просмотра (те же порты).
3. Создать проект Supabase `live-life` (Франкфурт), проверить, что включён TOTP, применить схему из ветки `astro` (`supabase db push` только к **новому** проекту).
4. Настоящий перенос: тот же `migrate.sh` с `--apply`, в конце `MIGRATION CHECK PASSED`.
5. Cloudflare, одновременно с вливанием: команды сборки `npm run build` / `npx wrangler deploy` вместо OpenNext и переменные с новыми именами и ключами `live-life` (`ops/cloudflare/README.md`, раздел «Переход»). Supabase `live-life` → URL Configuration — адрес сайта.
6. Влить `astro` в `main` — только по решению владельца.
7. После выкладки: `/api/health`, проверки кэша и заголовков (`ops/cloudflare/README.md`), Worker → Metrics → CPU time (если больше 10 мс — Workers Paid), вход волонтёра.
8. Копии: секреты `SUPABASE_DB_URL`, `SUPABASE_URL` нового проекта в репозитории копий, новые версии скриптов, ручной запуск backup и restore-drill (`ops/backup/README.md`, раздел «Переход»).
9. Волонтёрам: войти заново (пароль и приложение прежние); `.env.coordinator` — адрес и ключ нового проекта.

## Как работать с владельцем проекта

- **По одному шагу за раз.** Один вопрос или одно действие в сообщении, следующий шаг — после ответа.
- **Доказывать, что работает,** а не только «сделать»: проверка на локальном Supabase, затем на живом сайте, с выводом команд.
- Интерфейсы Cloudflare, Supabase и DeepL меняются. Если инструкция не совпадает с экраном, попросите снимок экрана и работайте по нему.
- Секреты (ключи, токены, пароли) никогда не присылаются в чат и не видны на снимках. Ключи для API вводятся только в форме секретов окружения.
- Репозиторий **публичный**: никаких личных данных и секретов в коммитах. Папка `scripts/data/` в git не добавляется.

## Локальная проверка (для Claude Code)

- Docker: если `docker info` не отвечает, удалить `/var/run/docker.pid` и `/var/run/docker.sock` и запустить `dockerd` в фоне.
- Supabase: `npx -y supabase@2.122.0 start`; для тестов панели временно включить TOTP в `supabase/config.toml` (`[auth.mfa.totp]`) и потом вернуть (`git checkout supabase/config.toml`).
- Сеть npm и локальные адреса: `export npm_config_noproxy=localhost,127.0.0.1 NO_PROXY=localhost,127.0.0.1 no_proxy=localhost,127.0.0.1`.
- Сайт: `npm run build`, затем `npx wrangler dev --port 8788` (переменные в `.dev.vars`). После пересборки перезапускать `wrangler dev`, иначе старый процесс отдаёт страницы без CSS.
- Тесты: `npx playwright test --trace off` (переменные `E2E_*` — в начале `e2e/*.spec.ts`); `npx tsc --noEmit -p .`, `npm run lint`, `npx astro check`; база — `supabase db reset --local && supabase test db`.
- Playwright: `executablePath: "/opt/pw-browsers/chromium"`.
- Учебная тревога копий поднимает свой Supabase на стандартных портах: основной локальный на это время останавливать.
- Для изменений `package-lock.json` использовать `npx -y npm@11` (npm 10 теряет поля `libc`).
