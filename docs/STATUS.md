## Как работать с владельцем проекта

- **По одному шагу за раз.** Один вопрос или одно действие в сообщении, следующий шаг — после ответа.
- **Доказывать, что работает,** а не только «сделать»: проверка на локальном Supabase, затем на живом сайте, с выводом команд.
- Интерфейсы Cloudflare, Supabase и DeepL меняются. Если инструкция не совпадает с экраном, попросите снимок экрана и работайте по нему.
- Секреты (ключи, токены, пароли) никогда не присылаются в чат и не видны на снимках. Ключи для API вводятся только в форме секретов окружения.
- Репозиторий **публичный**: никаких личных данных и секретов в коммитах. Папка `scripts/data/` в git не добавляется.

## Как устроено

| Что | Где | Подробности |
|---|---|---|
| Сайт | Cloudflare Workers Free, `https://a11y-shelter-system.priyut-md.workers.dev` | `ops/cloudflare/README.md` |
| Выкладка | Cloudflare сам собирает и выкладывает **только** ветку `main` (сборки веток выключены) | там же |
| База, вход, фото | Supabase Free, проект `czbuyirmoixortuhlekv` | `supabase/` |
| Переводы ro/en | DeepL API Free: сразу после сохранения в панели и ночью в 02:00 UTC | `lib/translateStale.ts` |
| Резервные копии | приватный репозиторий `a11y-shelter-backups`: каждую ночь, учебное восстановление по воскресеньям | `ops/backup/README.md` |
| Мониторинг | UptimeRobot на `/api/health`, письма на почту | |
| Действия координатора | скрипты `scripts/*.ts`, запуск `node --env-file=.env.coordinator scripts/<скрипт>.ts …`, без `--apply` — пробный запуск | комментарий в начале каждого скрипта |

## Что осталось

**До открытия сайта людям:**

1. Проверить мгновенный перевод на Cloudflare: волонтёр меняет мелочь в проекте в панели, через минуту перевод должен быть на `/ro/…`. Пока этого никто не видел.
2. Блок пожертвований: сейчас в нём личная почта PayPal. Решить с владельцем, какие реквизиты должны быть видны всем.
3. Количества в нуждах похожи на заглушки («1 шт.»). Настоящие должен указать приют.
4. Каталог животных пуст: его заполняют волонтёры через панель.
5. Workers Paid ($5 в месяц): сайт тратит 15–120 мс процессорного времени на запрос при лимите 10 мс на бесплатном тарифе.
6. Свой домен (около $10 в год). После него: `workers_dev: false` в `wrangler.jsonc`, новый адрес в Cloudflare (Runtime и Build), Supabase (URL Configuration), UptimeRobot и `.env.coordinator`, затем `ALLOW_INDEXING=true`.

**Не проверено:** загрузка фото с iPhone/Safari (нет устройства).

**По расписанию:**

7. Во время пилота раз в неделю смотреть ошибки: Cloudflare → Worker → Metrics.
8. Раз в квартал вручную восстанавливать копию в новый проект Supabase (`ops/backup/README.md`).
9. После пилота отозвать токен Cloudflare только для чтения (сам истекает 12.12.2026).

## Локальная проверка (для Claude Code)

- Supabase: `npx -y supabase@2.122.0 start` (при необходимости сначала запустить `dockerd`). Для тестов панели волонтёра временно включить TOTP в `supabase/config.toml` и потом вернуть.
- Next: после проверки останавливать процесс `next-server`, иначе старая версия продолжит отвечать.
- Playwright: `executablePath: "/opt/pw-browsers/chromium"`, для живого сайта — `proxy: { server: process.env.HTTPS_PROXY }`.
- `next dev` переписывает блок в `AGENTS.md`: это изменение можно коммитить.
- Для изменений `package-lock.json` использовать `npx -y npm@11` (npm 10 теряет поля `libc`).
