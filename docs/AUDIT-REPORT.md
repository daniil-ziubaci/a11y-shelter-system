### Что проверено и оказалось в порядке

- **Вход и 2FA.** Неверный пароль и код дают общее сообщение без подробностей. Без кода (`aal1`) панель не открывается, данные не меняются: RLS требует `aal2` на каждую запись (pgTAP и проба через API: обновление `pets` вернуло 0 строк). Supabase не даёт при `aal1` подключить второе приложение (`403 insufficient_aal`) и сменить пароль (`401 insufficient_aal`) — проверено на локальной базе.
- **Защита форм.** Astro `security.checkOrigin` включён. Форма входа и выход с чужим `Origin` получают 403 (проверено). По исходнику `node_modules/astro/dist/core/app/origin-check.js` проверка смотрит `Sec-Fetch-Site` и `Origin` для форм; запросы с другим типом данных браузер без разрешения не отправит, а страницы читают только формы.
- **Перенаправления.** Все адреса после входа, выхода, приглашения и действий в панели — постоянные или начинаются с `/volunteer`. Попытки `//evil.example/`, `/\evil.example/` уводят только внутри сайта (проверено).
- **`/api/cron/translate`.** Без ключа и с неверным ключом — 401; ключ сравнивается за постоянное время. Без `CRON_SECRET` маршрут закрыт.
- **Служебный ключ.** Используется в двух местах: ночной перевод и удаление старых фото (после проверки «файл больше нигде не нужен»). В браузер и в сборку не попадает: все переменные объявлены `access: "secret"`, в код Worker (`wrangler deploy --dry-run --outdir`) и в файлы для браузера (`dist/client`) ключи не попадают (поиск значений локальных ключей). Единственная копия — `dist/server/.dev.vars`: её делает адаптер для `wrangler dev` на компьютере, на Cloudflare она не загружается, а при сборке на Cloudflare файла `.dev.vars` нет. Скрипты координатора берут его из `.env.coordinator`, файл в git не попадает (`.gitignore`: `.env*`).
- **Фото.** Сервер читает заголовок файла и принимает только WebP или JPEG нужного размера без EXIF/XMP, тип файла задаёт сам. Хранилище: загрузка только волонтёрам с `aal2` и только в `animals/` и `projects/`, перезапись и удаление — только служебным ключом.
- **Данные от пользователя.** Формы проверяются на сервере, в базе есть ограничения. Вывод экранируется Astro; единственный `set:html` (JSON-LD) экранирует `<`.
- **Ошибки и журналы.** Посетитель видит понятную страницу ошибки без технических подробностей. В журнал попадают идентификаторы записей и тексты ошибок, без паролей, ключей и почты.
- **RLS.** 543 проверки pgTAP, в том числе доступ анонима, не-волонтёра и волонтёра без второго фактора к каждой таблице и хранилищу.
- **Доступность.** axe (WCAG 2.0/2.1/2.2 A и AA) проходит на всех публичных страницах и страницах панели на двух ширинах экрана; есть ссылки «Перейти к содержимому», учтено `prefers-reduced-motion`.
- **Мёртвый код.** Неиспользуемых файлов и функций нет. Типы `src/lib/database.ts` совпадают со схемой (сверено с `supabase gen types`).

## Решения для вас

Каждое меняет права, схему базы или то, что видит пользователь, поэтому я их не делал.

- **Р1. Лимит попыток входа.** После своего домена: Cloudflare → Security → WAF → Rate limiting rules, правило для `POST /login` и `POST /volunteer/2fa/verify` (например, 10 попыток в минуту с одного адреса). Есть ли бесплатное правило на вашем тарифе, не проверено.
- **Р2. Регистрация в Supabase.** Проверить в новом проекте `live-life`: Authentication → Sign In / Providers → «Allow new users to sign up» выключено. Волонтёров создаёт `invite-volunteer.ts` служебным ключом, им регистрация не нужна (по коду скрипта; на боевом проекте не проверено).
- **Р3. Длина текстов животного.** Например: кличка до 50, описание фото до 300, здоровье до 500, описание до 3000 знаков — в форме, на сервере и в базе.
- **Р4. Срок сессии.** Сейчас вход живёт, пока волонтёр заходит хотя бы иногда. Ограничение времени сессии в Supabase — платная функция (по памяти, не проверено).
- **Р5. Права на столбцы `pets`.** Как у `projects`: разрешить волонтёру менять только поля формы и статус.
- **Р6. Полная CSP** для скриптов и картинок. Сначала в режиме «только отчёт».
- **Р7. Скрипт `remove-volunteer.ts`** вместо ручного удаления в панели Supabase.
- **Р8. Тайм-аут запросов к базе** (например, 5 секунд), чтобы при сбое страница ошибки появлялась быстрее.
- **Р9. Оповещение о сбое расписаний.** Например, ночной перевод после успеха «отмечается» во внешнем сервисе, и тот пишет, если отметки нет.
- **Р10. Закрепить действия GitHub** в копиях по номеру коммита.
- **Р11. README:** переписать разделы о нескольких приютах или пометить их как планы на будущее.
- **Р12. Индексы** `purchase_log(item_id)` и `pets(status)` — когда записей станет много.
