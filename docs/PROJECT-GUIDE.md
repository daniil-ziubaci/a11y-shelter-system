# Рассказ о проекте: как устроен сайт приюта

Этот текст для человека без опыта программирования. Предложения короткие. Каждое новое слово объясняется там, где встречается впервые. Все слова собраны ещё раз в словаре (раздел 5).

Речь идёт о новом сайте из ветки `astro`. **Ветка** — это отдельная версия проекта, которую можно менять, не трогая основную. Основная версия называется `main`; её сейчас видят посетители. Ветка `astro` ещё не влита в `main`.

---

## 1. Что это за проект и как он устроен целиком

Это сайт одного приюта для животных. На нём три главные части:

- **Каталог животных**: кто ищет дом, кто на лечении.
- **Нужды**: что приюту купить сейчас (корм, лекарства и так далее).
- **Проекты**: большие дела приюта, например ремонт или тёплые будки.

Сайт работает на трёх языках: русском, румынском и английском.

### Картинка словами

Представьте пять участников.

1. **Посетитель.** Человек с телефоном или компьютером. Он открывает адрес сайта в браузере. **Браузер** — программа для просмотра сайтов (Chrome, Safari, Firefox).
2. **Сайт (Worker на Cloudflare).** Cloudflare — компания, у которой по всему миру стоят компьютеры. Наш сайт — это маленькая программа на этих компьютерах. Она называется **Worker** («работник»). Когда посетитель открывает страницу, Worker собирает её и отправляет в браузер.
3. **База данных (Supabase).** Supabase — другая компания. У неё хранятся все записи: животные, нужды, проекты, волонтёры. **База данных** — это большие аккуратные таблицы. Worker спрашивает у базы нужные строки и вставляет их в страницу.
4. **Хранилище фото (тоже Supabase).** Фотографии лежат не в таблицах, а в отдельном хранилище, как папки с файлами. Браузер посетителя загружает фото прямо оттуда.
5. **Волонтёр.** Человек из команды приюта. Он входит в **панель волонтёра** — закрытую часть сайта по адресу `/volunteer`. Там он добавляет животных, отмечает покупки, меняет проекты. Для входа нужны почта, пароль и шестизначный код из приложения на телефоне.

Есть ещё помощники:

- **DeepL** — сервис автоматического перевода. Волонтёры пишут по-русски, DeepL переводит на румынский и английский.
- **GitHub** — сайт, где хранится код проекта. Там же каждую ночь делаются резервные копии базы (в отдельном закрытом хранилище).
- **UptimeRobot** — сервис, который каждые несколько минут проверяет, жив ли сайт, и пишет на почту, если нет.

Схема в одну строку:

```
Посетитель → Worker (Cloudflare) → База и фото (Supabase)
Волонтёр  → Worker → База (только после пароля и кода) → перевод через DeepL
```

## 2. Папки и важные файлы

Код лежит в одной папке (репозитории). **Репозиторий** — папка проекта вместе со всей историей изменений. Ниже — что в какой подпапке.

### `src/` — сам сайт

Здесь всё, что работает на Cloudflare. Обычно вам сюда заходить не нужно: это работа разработчика.

- `src/pages/` — **страницы**. Каждый файл — один адрес сайта. Например, `src/pages/[locale]/needs.astro` — страница нужд (`/ru/needs`, `/ro/needs`, `/en/needs`). Квадратные скобки `[locale]` значат «здесь подставляется язык».
  - `src/pages/volunteer/` — панель волонтёра.
  - `src/pages/login.astro` — вход.
  - `src/pages/api/health.ts` — проверка «жив ли сайт» (ей пользуется UptimeRobot).
  - `src/pages/api/cron/translate.ts` — ночной перевод.
- `src/layouts/` — **шаблоны**: общая «рамка» страниц (шапка, подвал, заголовок вкладки).
- `src/components/` — **кусочки страниц**: карточка животного, галерея, переключатель языка.
- `src/islands/` — **острова**: формы панели, которым нужна работа в браузере (например, уменьшение фото перед отправкой). Что такое остров — в разделе 4.
- `src/lib/` — **вспомогательный код**: проверка форм, работа с фото, переводы, подключение к базе. Например, `src/lib/supabase.ts` подключает сайт к базе, `src/lib/checkPhoto.ts` проверяет присланные фото.
- `src/messages/` — **словари интерфейса**: `ru.json`, `ro.json`, `en.json`. Здесь тексты кнопок и заголовков. Сюда можно заглянуть, если нужно поправить надпись на сайте. Ключи (слева от двоеточия) не трогайте, меняйте только текст справа, и во всех трёх файлах.
- `src/middleware.ts` — **middleware** («прослойка»): код, который срабатывает перед каждой страницей. Проверяет вход в панель, ставит защитные заголовки. Не трогать.
- `src/worker.ts` — запуск расписаний (ночной перевод, ежедневный запрос к базе). Не трогать.
- `src/styles/global.css` — цвета и общий стиль.

### `supabase/` — база данных

- `supabase/migrations/` — **миграции**: файлы, которые создают таблицы и правила доступа. Сейчас один файл `20261113000000_single_shelter.sql`. **Не трогать**: изменение схемы — дело разработчика.
- `supabase/tests/` — проверки базы (**pgTAP** — инструмент, который проверяет правила базы). Их 543.
- `supabase/config.toml` — настройки **локальной** базы на компьютере разработчика. На настоящий проект не влияет.

### `scripts/` — скрипты координатора

**Скрипт** — небольшая программа, которую запускают одной командой в терминале. Здесь лежат ваши инструменты: пригласить волонтёра, сбросить пароль, создать проект и так далее. Список с объяснениями: `scripts/README.md`. Сюда заходить нужно часто. Править сами скрипты не нужно.

Важное правило: **без слова `--apply` скрипт только показывает, что сделает**, и ничего не меняет.

### `ops/` — обслуживание

- `ops/backup/` — резервные копии и восстановление (`ops/backup/README.md`).
- `ops/cloudflare/README.md` — как настроен хостинг, переменные, проверки после выкладки, откат.
- `ops/migrate/` — перенос данных со старого сайта на новый (делается один раз).
- `ops/perf/` — замер скорости.

Сюда заходить, когда что-то настраиваете или восстанавливаете.

### `docs/` — документы

- `docs/STATUS.md` — где мы сейчас и что осталось. Читайте первым.
- `docs/RUNBOOK.md` — **что делать, если что-то сломалось**. Ваша главная памятка.
- `docs/AUDIT-REPORT.md` — отчёт проверки кода и список решений для вас.
- `docs/ASTRO-PORT-REPORT.md` — отчёт о переходе на Astro.
- `docs/PROJECT-GUIDE.md` — этот рассказ.

### `e2e/` — автоматические проверки сайта

**Playwright** — программа, которая сама открывает браузер, нажимает кнопки и проверяет результат. Её проверки лежат здесь. Не трогать без разработчика.

### `public/` — файлы «как есть»

Значок сайта и фото галереи «О приюте». Отдаются без изменений.

### Файлы в корне папки

- `package.json` — список библиотек и команд проекта. **Библиотека** — чужой готовый код, который проект использует.
- `package-lock.json` — точные версии библиотек. Не править руками.
- `astro.config.mjs` — настройки Astro (языки, кэш, переменные). Не трогать.
- `wrangler.jsonc` — настройки Worker для Cloudflare (имя, расписания). Не трогать без причины.
- `.env.example` — образец списка переменных (без настоящих значений).
- `README.md` — большое описание замысла проекта. Местами оно описывает планы на много приютов; код сейчас на один приют.
- `CLAUDE.md`, `AGENTS.md` — правила для помощника-ИИ.

### Чего не должно быть в репозитории

Файлы `.env.coordinator` и `.dev.vars` содержат ключи. Они есть только на вашем компьютере и никогда не попадают в git. Репозиторий публичный: его видит весь интернет.

## 3. Путь запроса

**Запрос** — это просьба браузера к сайту: «дай мне такую-то страницу» или «вот форма, сохрани её».

### Когда посетитель открывает страницу

Пример: человек открывает `https://<адрес сайта>/` .

1. **Выбор языка.** Адрес `/` без языка. Worker смотрит, какой язык выбран в браузере, и отправляет на `/ru`, `/ro` или `/en`. Этот ответ не запоминается, чтобы румын не получил русскую версию.
2. **Кэш.** **Кэш** — это «память» Cloudflare. Если ту же страницу недавно уже собирали (за последнюю минуту), Cloudflare отдаёт готовую копию сразу. Базу не спрашивают. Так быстрее и дешевле.
3. **Если копии нет**, запускается Worker. Сначала middleware: ставит защитные заголовки. **Заголовки** — служебные строки ответа, посетитель их не видит; например, «эту страницу нельзя показывать внутри чужого сайта».
4. **Страница спрашивает базу.** Например, страница каталога просит у Supabase список животных. При этом используется **публичный ключ**: он позволяет только читать опубликованное. Это обеспечивают правила базы (RLS, см. словарь).
5. **Перевод.** В каждой записи рядом с русским текстом хранится готовый перевод. Страница на `/ro` просто берёт румынский вариант. Переводчик в этот момент не вызывается.
6. **Сборка страницы.** Worker вставляет данные в шаблон и отправляет готовый HTML в браузер. **HTML** — язык, на котором написаны страницы.
7. **Фото** браузер загружает сам, прямо из хранилища Supabase.
8. Cloudflare запоминает страницу на 60 секунд (ещё 60 секунд может отдавать её, пока собирает свежую).

Если база недоступна, посетитель видит страницу «Что-то пошло не так» с кнопкой «Попробовать снова». Такая страница не запоминается.

### Когда волонтёр сохраняет животное

1. **Вход.** Волонтёр открывает `/login`, вводит почту и пароль. Worker передаёт их в Supabase. Если всё верно, Supabase выдаёт **сессию** — пропуск на время работы. Пропуск хранится в **cookie** (маленькой записи в браузере). Скрипты страницы его прочитать не могут.
2. **2FA (двухфакторный вход).** Одного пароля мало. Сайт просит шестизначный код из приложения (Google Authenticator и подобные). Это **TOTP** — код, который меняется каждые 30 секунд. После верного кода пропуск становится «полным» (в Supabase это называется уровень `aal2`). Без него панель не открывается, а база не даёт ничего менять.
3. **Форма.** Волонтёр заполняет кличку, описание, выбирает фото. Остров в браузере уменьшает фото и убирает из него скрытые данные (например, место съёмки).
4. **Отправка.** Браузер отправляет форму. Astro проверяет, что форма пришла с нашего же сайта, а не с чужого (защита **Origin**).
5. **Проверка на сервере.** Worker проверяет поля (не пустые, правильный возраст) и фото (только JPEG или WebP, правильный размер, без скрытых данных).
6. **Запись.** Фото уходит в хранилище, строка — в таблицу `pets`. Запись идёт от имени волонтёра, поэтому база сама проверяет: он в списке волонтёров и ввёл код.
7. **Старое фото.** Если фото заменили, сервер после ответа удаляет старые файлы, но только если они больше нигде не нужны.
8. **Сброс кэша.** Сайт говорит Cloudflare забыть запомненные публичные страницы. Посетители увидят изменение через несколько секунд.
9. **Перевод.** После ответа волонтёру сайт отправляет новые тексты в DeepL и сохраняет перевод. Если DeepL не ответил, ночью в 02:00 UTC (это 04:00 или 05:00 по Кишинёву) перевод попробуют ещё раз.
10. Волонтёр видит список животных.

## 4. Основы Astro в этом проекте

**Astro** — инструмент, на котором написан сайт. Он превращает файлы из `src/` в программу для Cloudflare. **Сборка** (команда `npm run build`) — это превращение кода в готовую программу. **Выкладка** — отправка этой программы на Cloudflare.

- **Страницы и маршруты.** Каждый файл в `src/pages/` — адрес. `about.astro` → `/about`. Папка `[locale]` даёт адреса для всех языков сразу. Это называется **маршрутизация по файлам**. **Маршрут** — правило «какой адрес какой файл показывает».
- **Файлы `.astro`.** Сверху, между линиями `---`, код, который выполняется на сервере (например, запрос к базе). Ниже — разметка страницы.
- **Серверная отрисовка (SSR).** Страница собирается на сервере при каждом запросе (у нас — в Worker). Посетитель получает готовый текст. Это быстро на слабом телефоне и удобно экранным дикторам. В `astro.config.mjs` это строка `output: "server"`.
- **Middleware.** Код в `src/middleware.ts`, который выполняется перед каждой страницей. Он проверяет вход и код 2FA и добавляет заголовки.
- **Острова.** Почти весь сайт — готовый HTML без программ в браузере. Но некоторым частям нужна живая работа в браузере: форме животного и проекта (уменьшить фото, показать подсказки). Такие части называются **островами**: «остров» живого кода в «море» обычного текста. Они написаны на **React** (библиотека для живых интерфейсов) и лежат в `src/islands/`. В странице это выглядит как `<PetForm client:load …/>`.
- **Кэш.** Публичные страницы помечаются «можно запомнить на 60 секунд» с ярлыком `public`. При сохранении в панели сайт просит забыть всё с этим ярлыком. Это делает `src/lib/page.ts` и `src/lib/panel.ts`.
- **Переменные окружения.** Адрес базы и ключи не записаны в коде. Astro читает их во время работы из настроек Cloudflare (`astro:env`). Список — в `astro.config.mjs`, образец — `.env.example`.
- **Связь с Cloudflare Workers.** Адаптер `@astrojs/cloudflare` превращает сайт Astro в Worker. Команда `npm run build` собирает, `npx wrangler deploy` выкладывает (на Cloudflare это делается автоматически из `main`). **Wrangler** — программа Cloudflare для запуска и выкладки Worker. На своём компьютере сайт запускается командой `npm run preview`.

## 5. Словарь

| Слово | Что значит |
|---|---|
| Ветка | Отдельная версия проекта. `main` — та, что на сайте; `astro` — новая. |
| Git | Программа, которая хранит историю изменений кода. |
| Коммит | Одно сохранённое изменение в истории git, с подписью «что сделано». |
| Push | Отправка коммитов с компьютера на GitHub. |
| Репозиторий | Папка проекта со всей историей изменений. |
| Worker | Программа сайта на компьютерах Cloudflare. |
| Cloudflare | Компания, на чьих компьютерах работает сайт. |
| Supabase | Компания, где хранятся база, входы и фото. |
| База данных | Таблицы с записями: животные, нужды, проекты, волонтёры. |
| Хранилище | Место для файлов (фото) в Supabase. |
| RLS | «Защита на уровне строк»: правила в самой базе, кто какую строку может читать и менять. Даже если сайт ошибётся, база не отдаст лишнего. |
| Миграция | Файл, который создаёт или меняет таблицы и правила базы. |
| TOTP | Шестизначный код из приложения, меняется каждые 30 секунд. |
| 2FA | Двухфакторный вход: пароль плюс код с телефона. |
| aal2 | Отметка Supabase «человек ввёл и пароль, и код». |
| Сессия | Пропуск после входа, чтобы не вводить пароль на каждой странице. |
| Cookie | Маленькая запись, которую сайт хранит в браузере (например, пропуск). |
| Секрет | Ключ или пароль, который нельзя показывать никому: ключ базы, ключ DeepL, `CRON_SECRET`. |
| Переменные окружения | Настройки программы, которые хранятся отдельно от кода (адрес базы, ключи). На Cloudflare — Runtime variables. |
| Публичный ключ (anon key) | Ключ базы, который может только читать опубликованное. Не страшно, если его увидят. |
| Служебный ключ (service role key) | Ключ базы, который может всё. Хранится только на Cloudflare и в `.env.coordinator`. |
| `CRON_SECRET` | Пароль, без которого нельзя запустить ночной перевод по адресу `/api/cron/translate`. |
| Расписание (cron) | Задача, которая запускается сама в нужное время. |
| Кэш | Временная копия страницы, чтобы отдавать её быстрее. |
| Middleware | Код, который выполняется перед каждой страницей. |
| Остров | Часть страницы с живым кодом в браузере. |
| SSR | Сборка страницы на сервере при каждом запросе. |
| Сборка (build) | Превращение кода в готовую программу. |
| Выкладка (deploy) | Отправка готовой программы на Cloudflare. |
| Откат (rollback) | Возврат прошлой версии программы. |
| Резервная копия | Снимок базы и фото, чтобы восстановить их после потери. |
| Учебная тревога (restore drill) | Проверка, что копию действительно можно восстановить. |
| DeepL | Сервис автоматического перевода. |
| Терминал | Окно для ввода команд текстом. |
| Скрипт | Небольшая программа, запускаемая одной командой. |
| Origin | Отметка браузера «с какого сайта отправлена форма». |
| Заголовок ответа | Служебная строка в ответе сайта, невидимая посетителю. |
| WCAG | Международные правила доступности сайтов для людей с нарушениями зрения, слуха, движения. |
| UptimeRobot | Сервис, который следит, открывается ли сайт. |

## 6. Как сделать типичные задачи

Все команды запускаются в терминале, в папке проекта на вашем компьютере. Общий вид:

```bash
node --env-file=.env.coordinator scripts/<скрипт>.ts … --apply
```

Сначала запускайте **без** `--apply`: скрипт покажет, что сделает. Потом то же с `--apply`.

- **Добавить волонтёра.** `scripts/invite-volunteer.ts почта`. Скрипт печатает одноразовую ссылку. Передайте её человеку лично. Он задаст пароль и настроит приложение для кода. Подробно: `docs/RUNBOOK.md`, раздел 4.
- **Волонтёр забыл пароль.** `scripts/reset-password.ts почта`. Человек откроет ссылку, введёт новый пароль и код из приложения.
- **Волонтёр потерял телефон.** `scripts/reset-2fa.ts почта`. Человек войдёт с паролем и настроит приложение заново.
- **Волонтёр уходит.** Сбросить код недостаточно. Удалите пользователя: Supabase → Authentication → Users → Delete user (`docs/RUNBOOK.md`, раздел 4).
- **Сменить свой пароль.** Попросите разработчика или запустите `reset-password.ts` на свою почту.
- **Добавить проект.** Волонтёр может сам: панель → «Проекты» → добавить. Или скриптом `scripts/create-project.ts --title "…" --description "…"`. Закрепить проект наверху может только координатор: `scripts/edit-project.ts "название" --pin`.
- **Исправить неточный перевод.** `scripts/edit-project.ts "название" --fix-translation ro "было" "стало"`.
- **Загрузить список нужд.** `scripts/load-needs.ts файл.jsonl` (формат — в `scripts/README.md`).
- **Поменять логотип или фото приюта.** `scripts/set-shelter-brand.ts`, `scripts/upload-shelter-photo.ts`.
- **Запустить перевод сейчас, не дожидаясь ночи.** Команда — в `ops/cloudflare/README.md`, раздел «Что работает само».
- **Что делать при сбое.** Откройте `docs/RUNBOOK.md`:
  - сайт не открывается — раздел 1;
  - пропали данные — раздел 2 (восстановление из копии);
  - пропали фото — раздел 3;
  - сломалось сразу после выкладки — откат: `ops/cloudflare/README.md`, раздел «Откат».

## 7. Что может сломаться и как это заметить

| Что ломается | Как заметить | Что делать |
|---|---|---|
| Сайт не открывается | Письмо от UptimeRobot; `/api/health` не отвечает | `docs/RUNBOOK.md`, раздел 1 |
| Supabase уснул (бесплатный проект засыпает после недели без запросов) | `/api/health` отвечает `error`, на сайте «Что-то пошло не так» | Supabase → Restore project. Ежедневный запрос в 14:00 UTC должен этого не допускать |
| Превышен лимит процессорного времени Cloudflare (10 мс на бесплатном тарифе) | Cloudflare → Worker → Metrics: ошибки `Exceeded CPU` | Workers Paid ($5 в месяц) |
| Кончился лимит DeepL | Новые тексты на `/ro` и `/en` остаются русскими; в ответе ночного перевода поле `deepl` пишет о лимите | Ждать нового месяца или платный тариф DeepL |
| Ночной перевод не запустился | Писем нет. Видно только в Cloudflare → Worker → Observability | Запустить вручную (раздел 6). Оповещение — решение Р9 в `docs/AUDIT-REPORT.md` |
| Ночная копия не сделалась | GitHub пишет письмо, если задача упала | `ops/backup/README.md` |
| Учебная тревога по воскресеньям красная | Письмо от GitHub | `ops/backup/README.md`; не откладывать |
| Выкладка сломала сайт | Ошибки сразу после изменения `main` | Откат (`ops/cloudflare/README.md`) |
| Волонтёр не может войти | Жалоба волонтёра | `docs/RUNBOOK.md`, раздел 4 |
| Кончилось место в Supabase (база или фото) | Supabase → Usage, письма от Supabase | Почистить лишнее или перейти на платный тариф |

Раз в неделю во время пилота смотрите Cloudflare → Worker → Metrics → Errors.

## 8. Что выучить в первую очередь

По шагам, от простого к сложному. Каждый шаг — примерно вечер.

1. **Терминал.** Как открыть, как перейти в папку (`cd`), как запустить команду и прочитать ответ. Попробуйте `ls` и `pwd`.
2. **Скрипты координатора.** Прочитайте `scripts/README.md`. Запустите любой скрипт **без** `--apply` и посмотрите, что он пишет.
3. **Памятка на случай сбоя.** Прочитайте `docs/RUNBOOK.md` целиком, пока ничего не сломалось. Найдите в Cloudflare вкладки Metrics и Deployments, в Supabase — Usage и Authentication → Users.
4. **Git и GitHub.** Что такое коммит, ветка, push. Как посмотреть историю (`git log --oneline`). Главное правило: никаких ключей в коммитах.
5. **Как сайт работает целиком.** Перечитайте разделы 1 и 3 этого рассказа. Откройте сайт и `/api/health`.
6. **Локальный запуск.** Запустите сайт у себя (`npm run preview`) с тестовыми данными (`scripts/seed-local.ts`). Так можно пробовать без риска.
7. **Учебник Astro** (раздел 4): первые три части. Потом найдите в `src/pages/` файл страницы, которую знаете, и сравните с тем, что видно в браузере.
8. **Правила доступа в базе (RLS).** Прочитайте начало файла миграции `supabase/migrations/20261113000000_single_shelter.sql`: там простыми словами описано, кто что может.
9. **Резервные копии.** Пройдите учебную тревогу по `ops/backup/README.md` сами, на своём компьютере.
