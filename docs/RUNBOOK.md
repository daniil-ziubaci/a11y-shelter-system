# Что делать, если что-то сломалось

Памятка для владельца сайта и координатора. Написана простыми словами. Каждая команда здесь проверена на локальной копии сайта 13.11.2026 (отметка **проверено**). Действия в интерфейсах Cloudflare, Supabase и GitHub проверить из рабочей среды было нельзя, они помечены **не проверено**: если экран выглядит иначе, сделайте снимок экрана (без ключей и паролей) и спросите.

Общие правила:

- Сначала успокойтесь и запишите время, когда заметили проблему. Ничего не удаляйте.
- Ключи, пароли и токены никогда не пересылайте в чат и не показывайте на снимках экрана.
- Команды запускаются в папке проекта на компьютере координатора. Файл `.env.coordinator` с ключами лежит только там.

## 1. Сайт не открывается

**Шаг 1. Проверьте, отвечает ли сайт.** Откройте в браузере адрес сайта и добавьте `/api/health`, например `https://<адрес сайта>/api/health`. Или в терминале:

```bash
curl -s -w ' [%{http_code}]\n' https://<адрес сайта>/api/health
```

Если всё в порядке, ответ такой (**проверено** локально):

```
{"status":"ok"} [200]
```

- Ответ `ok` — сайт и база работают. Если у вас страница всё равно не открывается, попробуйте другой браузер или телефон: возможно, проблема с интернетом.
- Ошибка 500 или 503 — сайт работает, но не достаёт до базы. Переходите к шагу 2.
- Нет ответа совсем — переходите к шагу 3.

Письмо от UptimeRobot приходит, когда этот адрес перестаёт отвечать.

**Шаг 2. Проверьте базу (Supabase).** **Не проверено.** Зайдите на supabase.com → ваш проект.

- Если написано, что проект на паузе (Paused), нажмите Restore project. Бесплатный проект ставится на паузу после недели без запросов. Ежедневный запрос к базе в 14:00 UTC (расписание Worker) должен этого не допускать, но если он не сработал, пауза возможна.
- Если Supabase пишет о сбое на своей стороне (status.supabase.com), остаётся ждать.

**Шаг 3. Проверьте Cloudflare.** **Не проверено.** Cloudflare → Workers & Pages → `a11y-shelter-system`.

- Вкладка Metrics: много ошибок `Exceeded CPU` значит, что сайту не хватает лимита бесплатного тарифа (10 мс на запрос). Решение — Workers Paid ($5 в месяц).
- Вкладка Deployments: если сайт сломался сразу после выкладки, выберите предыдущую выкладку и нажмите Rollback. Это вернёт прошлую версию кода, база не меняется.

## 2. Пропали данные (животные, нужды, проекты)

Не исправляйте ничего руками в базе: сначала убедитесь, что есть свежая копия.

**Шаг 1. Найдите копию.** Копии лежат в приватном репозитории копий на GitHub, в папке `db/` (файлы `ГГГГ-ММ-ДД.tar.gz.gpg`), фото — в `photos/`. Каждую ночь появляется новая копия. Хранятся копии за 60 дней, но 7 самых новых не удаляются никогда, даже если копии долго не делались. Более старые остаются в истории репозитория.

**Шаг 2. Проверьте копию учебной тревогой.** Она восстанавливает копию во временную базу на компьютере (нужен Docker) и сверяет всё. Настоящая база не трогается. **Проверено:**

```bash
export BACKUP_PASSPHRASE='пароль копий'
ops/backup/restore-drill.sh
```

В конце должно быть:

```
PASS  every pet photo opens (38 pets, 0 missing)
RESTORE DRILL PASSED
```

Каждое воскресенье эта же проверка сама запускается на GitHub (Actions → restore-drill). Если она красная, GitHub присылает письмо.

**Шаг 3. Восстановите копию в новый проект.** Восстанавливать нужно в **новый пустой** проект Supabase, а не поверх старого: так старые данные остаются для сравнения. Подробно по шагам: `ops/backup/README.md`, раздел «Восстановление». Главная команда (**проверено**: её запускают и учебная тревога, и перенос данных):

```bash
export TARGET_DB_URL='строка Session pooler нового проекта'
export TARGET_URL='https://<новый-проект>.supabase.co'
export TARGET_SERVICE_KEY='service_role ключ нового проекта'
export BACKUP_PASSPHRASE='пароль копий'
ops/backup/restore.sh db/ГГГГ-ММ-ДД.tar.gz.gpg photos
```

Последние строки:

```
Photos uploaded: 110 of 110 used by the site
Not uploaded (deleted from the site earlier, kept in photos/): 0
```

После этого (**не проверено** из рабочей среды, нужен доступ к Cloudflare и Supabase):

1. Cloudflare → Worker → Settings → Variables and Secrets: заменить `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` на ключи нового проекта.
2. Supabase (новый проект) → Authentication → URL Configuration: адрес сайта.
3. Адреса фото животных: запрос из `ops/backup/README.md`, шаг 5.
4. Секреты копий в репозитории копий: `SUPABASE_DB_URL` и `SUPABASE_URL` нового проекта, иначе копии будут делаться со старого.

## 3. Пропали фото

- Если файла фото нет, сайт не показывает значок битой картинки: карточка животного берёт основное фото вместо уменьшенной копии, а если нет и его, показывается пустая плашка. **Проверено** тестом.
- Быстрее всего: волонтёр открывает животное или проект в панели и загружает фото заново. Старые файлы при этом удаляются сами. **Проверено** тестом.
- Все фото есть в репозитории копий, в папке `photos/`, с теми же путями, что и в хранилище: оттуда можно взять нужный файл и отдать волонтёру. Удалённые с сайта фото в `photos/` тоже остаются.
- Если пропало всё хранилище, восстановите копию целиком (раздел 2, шаг 3): `restore.sh` загружает и фото.

## 4. Восстановить доступ волонтёру

Волонтёр входит по почте, паролю и шестизначному коду из приложения на телефоне. Все команды ниже без `--apply` только показывают, что сделают, и ничего не меняют. Ссылки передавайте человеку лично (например, в мессенджере), они одноразовые.

**Забыл пароль, телефон с приложением на месте.** **Проверено:**

```bash
node --env-file=.env.coordinator scripts/reset-password.ts почта@волонтёра --apply
```

Скрипт печатает ссылку. Человек открывает её, вводит новый пароль два раза и код из приложения. Без верного кода пароль не меняется. Новый пароль должен отличаться от старого.

**Потерял телефон (или удалил приложение), пароль помнит.** **Проверено:**

```bash
node --env-file=.env.coordinator scripts/reset-2fa.ts почта@волонтёра --apply
```

```
Удалено факторов: 1
Попросите человека сразу войти и заново настроить приложение.
```

Человек входит с паролем, и сайт сам открывает настройку двухфакторного входа с новым QR-кодом.

**Потерял и пароль, и телефон.** Сначала `reset-2fa.ts`, затем `reset-password.ts` (обе команды выше). Страница пароля тогда не спрашивает код, а после входа сайт предлагает настроить приложение заново. **Проверено.**

**Новый волонтёр.** **Проверено:**

```bash
node --env-file=.env.coordinator scripts/invite-volunteer.ts почта@волонтёра --apply
```

Для человека, у которого уже есть вход, приглашение не создаётся (Supabase отвечает, что почта уже зарегистрирована): используйте `reset-password.ts`.

**Волонтёр уходит.** Готового скрипта нет. Сброс второго фактора (`reset-2fa.ts`) доступ **не закрывает**: человек входит со старым паролем и сам настраивает новый код. Закрыть доступ: Supabase → Authentication → Users → найти почту → Delete user (**не проверено**: экран может выглядеть иначе). Вместе с пользователем база сама удаляет его из таблицы `volunteers` (**проверено** на локальной базе 14.11.2026). Данные, которые он вносил, остаются.

## 5. Кому писать

- Ошибка в коде сайта: разработчику, с временем, адресом страницы и снимком экрана (без паролей).
- Список всех скриптов координатора: `scripts/README.md`.
- Копии и восстановление подробно: `ops/backup/README.md`.
